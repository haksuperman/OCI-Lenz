# 검증 근거

- 13개 회귀를 먼저 작성해 미구현/기존 상단 제목 공백 실패를 확인하고 수정했다.
  경계 지침의 무변경·결정성, 실제 측면 버스/외부 선 꺾임/컨테이너 도착점,
  긴 제목·최소 크기, 중첩 자식 프레임, 직선 통과선, 추가 꺾임/우회 거부,
  연결 구조가 같은 축소 수용, 제목의 16px 간격을 검증한다.
- 최종 전체 423개 테스트가 OCI SDK 2.192.0 및 최소 지원 2.191.0에서 통과했다.
  하네스 구조 check와 git diff --check 통과. phase 상태는 실행기가 관리한다.
- 가상 fanout 및 nlb-backends의 이전 AI 배치에 실제 공통 시각 검토를 적용했다.
  두 수정안 모두 lower_loss로 채택됐으며, 리전 면적이 각각 7.44%, 3.77% 줄었다.
  이는 해당 두 사례의 측정값이며 모든 인벤토리의 축소율을 보증하지 않는다.
- 각 선의 source/target, start/end arrow 및 연속 구간의 방향 순서가 동일하다.
  화살촉 혼잡, 짧은 단말, 리소스/제목 침범, 선 겹침, 대각선, 모호한 교차,
  연결 통로 부족, 분기 행 방해는 모두 0을 유지한다. 꺾임 수도 16/8 그대로다.
  관련 행의 길이는 줄어들 수 있으며 모든 리소스 좌표가 고정됐다는 뜻은 아니다.
- 최종 네이티브 XML 검증과 정확한 재생성, 같은 파일의 Desktop PNG 내보내기,
  전체 PNG payload/CRC 검사 통과. architecture.png는 각각 1950×1136,
  1360×896이며 공식 아이콘·네이티브 라벨·T 분기·별도 도착점의 잘림을 확인했다.
  상단 제목은 지역 바로 위 일정 간격에 붙으며 자원/선 geometry를 바꾸지 않는다.
- 최종 AI 시각 평가는 두 사례 모두 excessive_whitespace로 needs_review다.
  fanout의 코드 품질에도 내부 간격/희소 컨테이너 여백 검토가 남는다.
  nlb-backends 코드 품질은 clear이나 AI 판정과 구분하며 전체 시각 통과로
  보고하지 않는다. 원래 시각 보고서를 최종 통과로 덮어쓰지 않았다.
- 일반 패키지를 설치하고 저장소 밖 isolated Python에서 변경된 설치 모듈과
  최종 소스의 일치를 확인했다. 고객사 자료와 실제 OCI 조회는 사용하지 않았다.
  검증 그림과 상세 보고서는 저장소 밖 가상 데이터 검증 경로에 유지한다.
  자동 commit/push 없음.
