# Common connector rules for future generation
Read AGENTS.md and project HARNESS/PRD/ARCHITECTURE/ADR, architecture/ai/routing,
quality/visual_review and connector tests. Input: alias scene, actual official
icon dimensions, existing API edges and immutable API container parents.
Interface: versioned connector guides in every fresh AI request/plan, common
native router, objective validation. Scope: use painted glyph anchors rather
than caption/card or container midpoints. Single-content API containers expose
a content-row alignment guide for one-to-one visible configured edges. Enforce
it for fresh plans, retain legacy replay with explicit quality warning. Reuse
source-aligned body ports only below real headers. Prefer straight clear routes
and remove unnecessary old bends; retain necessary obstacle/fanout turns.
AC: tests fail first, multiple container types not names, ambiguous ownership
not guessed, fresh-plan rejection and repair, no header/card intrusion, full
suite and independent fresh synthetic PNGs with direct mapping wires.
Prohibitions: per-customer/resource-name offsets, PNG-only patching, fabricated
child edges/ownership, local movement of AI rectangles, deleted evidence,
OCI queries/writes, secrets/raw data, customer artifacts in Git, agents,
commits/pushes or manual phase completion.
